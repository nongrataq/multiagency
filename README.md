# StudyFlow

StudyFlow помогает заниматься по собственным конспектам. Он принимает Markdown и TXT, ищет в них нужные разделы и использует найденный материал для объяснений, планов подготовки и коротких тестов. Ответы показывают использованные разделы; тест можно пройти в приложении, а результаты и история сохраняются между запусками.

Проект рассчитан на одного пользователя и локальный запуск через Ollama. Обращения к платным облачным моделям не нужны.

## Возможности

- Загрузка и переиндексация конспектов.
- Поиск по разделам и связям между соседними разделами.
- Объяснения и планы подготовки с привязкой к материалам.
- Тесты с тремя вопросами, автоматическая оценка и история результатов.
- Проверка ссылок и содержания перед сохранением ответа.
- История диалога, прогресс по темам и технические уведомления.

## Архитектура

LangGraph управляет последовательностью шагов: маршрутизация запроса, поиск источников, подготовка ответа и проверка. Для теста модель выбирает вопросы из коротких фрагментов конспекта, а приложение связывает их с точными источниками и пояснениями. Ответ не сохраняется, если проверка не пройдена.

Роли моделей разделены:

| Роль | Модель | Назначение |
|---|---|---|
| Маршрутизатор | `d3:2b` | Выбирает режим: объяснение, план или тест |
| Планировщик | `qwen3.5:0.8b` | Формирует тему поиска по запросу |
| Автор | `qwen3.5:2b` | Готовит объяснение, план или вопросы теста |
| Проверяющий | `gemma4:e2b` | Сверяет содержание и ссылки с найденными источниками |

Запросы к моделям выполняются последовательно. Время ответа зависит от выбранных моделей и доступных вычислительных ресурсов; первый вызов может включать загрузку модели.

Для материалов и прогресса используется SQLite: индекс документов, сохранённые ответы, результаты тестов и checkpoints диалога. Поиск построен на SQLite FTS5 и структуре разделов документа; векторная база и embeddings не используются.

## Запуск через Docker

Нужны Docker и работающий на хосте Ollama с четырьмя моделями из таблицы выше. При стандартной установке Ollama сервер обычно запускается вместе с приложением. Если используется подготовленный runtime проекта, запустите его в отдельном окне:

```sh
sh scripts/serve-ollama.sh
```

Затем из корня проекта соберите и запустите приложение с мониторингом:

```sh
docker compose up -d --build
```

Откройте [http://localhost:8501](http://localhost:8501), загрузите конспект в боковой панели и выберите задачу. Интерфейс Phoenix доступен на `http://localhost:6006`, Prometheus — на `http://localhost:9090`. Состояние данных сохраняется в Docker volumes.

Чтобы остановить сервисы, не удаляя сохранённые данные:

```sh
docker compose down
```

Модели скачиваются один раз в Ollama на хосте:

```sh
ollama pull qwen3.5:0.8b
ollama pull qwen3.5:2b
ollama pull gemma4:e2b
ollama pull d3:2b
```

## Нативный запуск приложения

Для запуска интерфейса без Docker нужны Python 3.12 и работающий Ollama:

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/pip install --no-deps -e .
.venv/bin/python -m studyflow.serve --server.headless=true
```

Если Ollama слушает нестандартный адрес, задайте `OLLAMA_URL` перед запуском. Пример переменных находится в `.env.example`.

## Проверки и изоляция

Быстрые автоматические проверки выполняются без вызовов моделей:

```sh
.venv/bin/pytest -q
```

Для eval на настоящих моделях нужен запущенный контейнер приложения и загруженные модели:

```sh
docker compose exec app python -m studyflow.evaluate
```

Compose используется для локального запуска и наблюдаемости. Для демонстрации изоляции приложение разворачивается в отдельной Linux VM на Lima. Конфигурация находится в `infra/lima.yaml`, установочный и проверочный сценарии — в `infra/install-guest.sh` и `infra/verify-guest.sh`.
